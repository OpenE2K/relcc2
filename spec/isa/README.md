# ISA operation database

`binutils-ops.yaml` lists every operation MCST binutils can assemble. It is
generated by `tools/isa-extract/extract_binutils.py` from:

- `opcodes/e2k-opc.h`: the generated ALU operation table
- `opcodes/e2k-opc.c`: hand-written control operations
- `include/opcode/e2k.h`: struct layouts and constants

The binutils commit is recorded in the file header. To regenerate:

```
python3 tools/isa-extract/extract_binutils.py
```

## Fields

| Field | Meaning |
|---|---|
| `isets` | ISA versions (elbrus-vN) where the entry is valid. Bit N-1 of binutils' `iset_mask`. |
| `template`, `alopf` | Binutils template struct and ALU operation format (ALOPF1, ALOPF11, …). |
| `opc` | Opcode (ALS.cop). |
| `channels` | ALU channels (0–5) the entry may be placed in. |
| `args` | Register formats of the operands, in table order: `s` 32-bit, `d` 64-bit, `q` 128-bit, `p` packed 128-bit. Padded to the struct's array length. The role of each position depends on the format; see [bundle.md](bundle.md#operand-roles-per-format-checked-except-where-marked). |
| `flags` | `MAS`, `LOAD`, `STORE`. |
| `opce`, `ales_opce`, `ales_opc2`, `cmpopce`, … | Extra encoding fields, depending on the format. `ales_opc2` is keyed by channel when it differs per channel. |
| `aliases` | Other mnemonics binutils accepts for the same bits. |

One mnemonic can have several entries: per ISA version, per set of channels,
or per format. gas links them by name.

## Encoding check against gas

`tools/isa-extract/check_encodings.py <dir with e2k-linux-as>` predicts the
ALS and ALES syllables of every operation from this database, assembles each
one with gas for every ISA version and allowed channel, and compares the
bytes. It also exercises the wide-instruction layout in
[bundle.md](bundle.md).

Against binutils 2.41-29.023 it passes for all 24,238 cases on v2–v7. Not
covered yet:

- formats with memory, AAU or state-register operands, merges and
  `ibranchd`/`icalld`, listed in the tool's output;
- operations that take two channels;
- `_lt3` forms, whose src3 must be a literal.

## Decoder check against objdump

`tools/isa-decode/e2kdis.py` is a decoder written only from this directory:
[bundle.md](bundle.md), `binutils-ops.yaml` and `registers.yaml`.
`tools/isa-decode/compare_objdump.py` checks that it decodes gas output
identically to MCST objdump. The corpus is built by
`tools/isa-decode/build_corpus.sh` from C compiled by Unipro's clang and
from hand-written assembly, for v3–v7.

Against binutils 2.41-29.023: 6,826 of 6,836 bundles match. The other 10 are a
known objdump bug, listed in [bundle.md](bundle.md#known-objdump-bugs).

`registers.yaml` (state and AAU register names and numbers) is generated by
`tools/isa-extract/extract_registers.py`.

## Cross-check against the opcode spreadsheet

`tools/isa-extract/compare_sheet.py` compares the extracted data with the
`e2k_opcodes_new` sheet, which was generated from an older binutils that still
shipped the table generator. The sheet keeps the generator's more detailed
format names (`ALOPF21_MERGE`, `_LT3`, `_MAS`, `ALOPF21_LOG`), which current
binutils has flattened.

Result against binutils 2.41-29.023:

- All 1,510 sheet mnemonics are present in binutils, and their opcodes agree.
- Binutils has 1,586 more mnemonics, counting alias spellings. Almost all are
  `plog`/`qplog` truth-table spellings (hex, decimal and named), which the
  sheet keeps as `plog_0xXX` templates:
  - 1,025 first appear in v5: all `plog`/`qplog` forms except `ldaaqp`;
  - 548 first appear in v7: 517 `qplog_*_lt3` forms, and 31 new operations.
- Aside from those, a few operations first appear in v1, v3 or v6.
- 14 disagreements, none of them in v3–v6:

| Mnemonic | Version | binutils | sheet | Explanation |
|---|---|---|---|---|
| `getsod` | v1, v2 | channels 0,1 | channels 0,1,3,4 | Narrowed in newer binutils. |
| `aptoap`, `cudtoap`, `gdtoap`, `getva` | v7 | absent | present | Dropped for v7, whose protected mode is incompatible (see `link_alf_opcodes` in `e2k-opc.c`). |
| `vfsi` / `getpl` | v7 | opcode 0x63 in channels 1,4 is `getpl` | `vfsi` | On v7 that slot moves from `vfsi` to `getpl`, matching the paired-channel quad `getpl` described in `include/opcode/e2k.h`. |
| `qpaes*`, `qpkuz*` | v7 | channels 1,4 or 2,5 | channel 1 or 2 only | Widened in newer binutils. `add_to_insn_table` still removes channels 3–5 on elbrus-maket32c. |
