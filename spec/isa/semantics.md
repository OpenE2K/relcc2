# Operation semantics

What the operations a C compiler emits actually compute: operand order,
inverted forms, extension, out-of-range shift counts, division corner
cases, compare predicates, NaN handling. [bundle.md](bundle.md) and
`binutils-ops.yaml` give encodings and channels; this page gives the
behaviour.

Status: **[hw]** observed on an Elbrus 4C (elbrus-v3) by
`tools/isa-probes/semantics.c` (wrappers generated by
`gen_semantics.py`); **[guide]** from the MCST programming guide, chapter
10. MCST's qemu agrees with the hardware on every case it can run; it
aborts at the first trap ("exception handling is unimplemented").
Latencies are in [timing.md](timing.md).

32-bit (`...s`) operations below were run under `setwd dbl = 0`: they
write the low half of the destination and keep the upper half
([registers.md](../abi/registers.md), `dbl`).

## Integer arithmetic and logic [hw]

| Operation | Result |
|---|---|
| `subd a, b, dst` | a − b. (`rsub` exists only as the second stage of combined operations.) |
| `andnd a, b, dst` | a & ~b (the **second** operand is inverted) |
| `ornd a, b, dst` | a \| ~b |
| `xornd a, b, dst` | a ^ ~b |
| `merged a, b, dst, pred` | **a when pred is false**, b when true: the reverse of `pred ? a : b`. `~%predN` is accepted. |
| `sxt n, src, dst` | n = 0, 1, 2: sign-extend 8, 16, 32 bits; n = 4, 5, 6: **zero**-extend 8, 16, 32 bits; 3 = 2, 7 = 6. The guide (10.3.8) has the sign bit the other way round; lcc emits `sxt 0x1` for `short`, `0x5` for `unsigned short` |
| `smulhd a, b`, `umulhd a, b` | high 64 bits of the signed / unsigned 128-bit product |
| `popcntd`, `popcnts` | number of set bits |
| `lzcntd`, `lzcnts` | leading zeros; 64 (32) for zero |
| `bitrevd`, `bitrevs` | bit reversal |

There are no remainder operations: compute a % b as a − (a / b) × b.

## Shifts and rotates [hw]

`shl`, `shr` (logical), `sar` (arithmetic), `scl`, `scr` (rotate left,
right), each in `s` (32-bit) and `d` (64-bit) forms. The count is taken
**modulo the operand width**: `shld` by 64 or 128 returns the operand
unchanged, by 65 shifts by 1; `shls` by 32 returns it unchanged. Only the
low bits of the count register matter: `shls` ignores the count's upper
32 bits (a count of `0xaaaaaaaa00000001` shifts by 1), `shld` by
`0xffffffffffffffff` shifts by 63. For GCC: `SHIFT_COUNT_TRUNCATED` holds.

## Division [hw]

| Case | Result |
|---|---|
| `sdivd MIN, -1`, `sdivs MIN, -1` | MIN, no trap |
| negative dividend | truncates toward zero (−7 / 2 = −3) |
| `sdivd`, `udivd`, `sdivs` by zero | **SIGFPE, `si_code` `FPE_INTDIV`** |

Division by zero traps, so a compiler must not move a division where it
might not have been executed, unless it uses the speculative form
(`,sm`), which defers the fault into the result tag.

## Integer compares [hw]

Compares write a predicate. All of them evaluate `a − b` and test it
like x86 flags; `cmp<c>db` compares 64 bits, `cmp<c>sb` 32 bits:

| `c` | True when |
|---|---|
| `o` | signed overflow of a − b |
| `b` | a < b unsigned |
| `e` | a = b |
| `be` | a ≤ b unsigned |
| `s` | a − b is negative (sign bit), not "signed less" |
| `p` | the low byte of a − b has even parity |
| `l` | a < b signed |
| `le` | a ≤ b signed |

There are no `ne`, `gt`, `ge`, `a`, `ae` forms: swap the operands or use
the negated predicate (`~%predN`) in the consumer.

## Floating-point compares [hw]

`fcmp<c>db` (double) and `fcmp<c>sb` (single) into a predicate, with `c`
in `eq`, `lt`, `le`, `uod` (unordered), `neq`, `nlt`, `nle`, `od`
(ordered). There is no `gt`/`ge`: swap the operands. With a NaN operand:

| Compares | Quiet NaN | Signalling NaN |
|---|---|---|
| `eq`, `neq`, `uod`, `od` | no exception | invalid |
| `lt`, `le`, `nlt`, `nle` | **invalid** | invalid |

So `lt`/`le` are the signalling compares IEEE 754 requires for C's `<`
and `<=`, and `eq`/`uod` are quiet. `isless` and friends need a quiet
`uod` check first. `neq`, `nlt`, `nle` are true for unordered operands.

## FP min, max and combined operations [hw]

- `fmaxd a, b` / `fmind a, b` follow x86 `maxsd`/`minsd`, not C's
  `fmax`/`fmin`: if either operand is a NaN, or both are zeros, the result
  is **b**. (`fmaxd NaN, 1` = 1, `fmaxd 1, NaN` = NaN, `fmaxd 0, −0` =
  −0.) They implement `a > b ? a : b`, so a compiler may use them only
  where that is the source's semantics (or under `-ffinite-math-only`
  with no signed-zero concerns).
- `fmul_addd a, b, c, dst` = (a × b) + c with **two roundings** (not
  fused): `(1 + 2^-30)(1 − 2^-30) − 1` gives 0, not −2^-60. Combined FP
  operations may be used only under `-ffp-contract=fast`, never for
  `fma()`.
- Double square root is two operations, `fsqrtid` then `fsqrttd`, which
  together give the correctly rounded result [guide 10.4.2]; `fsqrts` is
  one.

## Other facts [guide]

- `getsp src2, dst`: src2 is a 32-bit signed operand; a negative value
  allocates that many bytes on the user stack, and dst receives the new
  stack pointer (guide 10.7.1; `getsp 0, dst` reads it).
- 80-bit operations (`fx*`), their registers and FP state:
  [registers.md](../abi/registers.md), "Extended parts and `long double`".
