# Loop mode, loop counters and rotation

E2K has hardware support for counted and software-pipelined loops:

- a **loop status register** `%lsr` that counts iterations and splits a
  pipelined loop into prologue, kernel and epilogue;
- per-instruction controls: the `loop_mode` bit, `alc` (advance the
  loop counters), the `%LOOP_END` / `%NOT_LOOP_END` transfer conditions,
  and predicates derived from the counters (`%pcntN`, `%lcntex`);
- **rotating registers**: `abn` renames the based registers `%b[]` and
  `abp` the predicates `%pred0..psz`, so each iteration of an
  overlapped loop gets fresh registers under the same names.

A one-instruction loop-mode loop runs one iteration per cycle; the back
edge costs nothing. [apb.md](apb.md) builds on this (array prefetch is
correct only in a `loop_mode` loop counted by `%lsr`).

- **[hw]**: run on the Elbrus 4C (elbrus-v3) by

- **[source]**: the kernel (`arch/e2k/include/asm/cpu_regs_types.h`

  `alc`, `translate-cds.c` stores and `%pcnt`, `translate-pls.c`

## Registers [source, hw]

`%lsr` (loop status register, `rrd`/`rwd` number 0x83):

| Bits | Field | Meaning |
|---|---|---|
| 0–31 | `lcnt` | loop counter: iterations left in the kernel |
| 32–36 | `ecnt` | epilogue counter: extra iterations after `lcnt` runs out |
| 37 | `vlc` | the counter is valid; without it the loop never ends [hw] |
| 38 | `over` | set by the `alc` that ended the loop; read as `%lcntex` |
| 39 | `ldmc` | loads manual control: 1 keeps `mova` working in epilogue iterations [hw] |
| 40–47 | `ldovl` | load overlap: undocumented (only named in the kernel; neither qemu implements it); no effect seen on ordinary loads or `mova` results at 0, 1, 2, 255 [hw]; lcc always writes 255 |
| 48–52 | `pcnt` | prologue counter |
| 53–59 | `strmd` | how many stores of the last iteration still write |
| 60 | `semc` | side effects manual control: no store suppression at all |

`%ilcr` (initial loop counters, 0x87) has `lcnt`, `ecnt` and `pcnt` at
the same places. **Writing `%lsr` also writes those fields of `%ilcr`**
[hw]; the loop doesn't change `%ilcr`, so `%ilcr − %lsr` is the number
of iterations done (the kernel uses this to restart array prefetch,
apb.md). v5+ add `%lsr1` (0xc3) and `%ilcr1` (0xc7): **`%lsr1` is the 64-bit
loop counter** [hw: Elbrus-8C2, `loops.c` built with `-DLOOPS_V5`].
Writing it sets the count: after `%lsr` with `lcnt` 5, writing `%lsr1`
= 7 makes the loop run 7 iterations and `%lsr` read back `lcnt` 7
(also 2, 1, 100; 0 behaves as `lcnt` 0 and runs once), and
`%lsr1` = 2³² + 3 runs exactly 4,294,967,299 iterations. Writing `%lsr`
**after** `%lsr1` resets `%lsr1` to the new `lcnt`, so write `%lsr`
first (control fields) and `%lsr1` second (the count), as lcc does
(`rwd %lsr` then `rwd n, %lsr1`). Each write also sets `%ilcr1`, which
the loop leaves alone; `%lsr1` reads 0 after the loop. `ecnt`, `pcnt`
and the store rules work as with `%lsr` alone. The kernel saves `%lsr`, `%lsr1`, `%ilcr` and `%ilcr1` in a
signal context [source], and they are scratch across calls
([registers.md](../abi/registers.md)).

`rwd %lsr` takes 4 cycles to take effect: a `rrd %lsr` 1–3 cycles later
reads the old value ([timing.md](timing.md)), and a loop whose first
`alc` comes 1–3 cycles after the write runs **one iteration too many**
(6 instead of 5) [hw]. On v6 (the Elbrus-2C3) the same loop runs **one**
iteration and leaves (`early1`–`early3`; 4 cycles is enough there too).
Write `%lsr` at least 4 cycles before the loop.

## Instruction controls [source: bundle.md, gas]

| Control | Where | Effect |
|---|---|---|
| `loop_mode` | HS bit 10 (`lm`) | this instruction's stores obey the prologue/last-iteration rules below |
| `alc alcf=F, alct=T` | SS bits 16–17 | advance the counters if the instruction's transfer is not taken (F) / taken (T) |
| `abn abnf=F, abnt=T` | SS bits 21–22 | rotate `%b[]` likewise |
| `abp abpf=F, abpt=T` | SS bits 18–19 | rotate the predicates likewise |
| `abg N` (gas: a number, 2 = `abgi`, 1 = `abgd`) | SS bits 23–24 | rotate the global registers' based area (`%bgr`, below) |
| `ct ... ? %NOT_LOOP_END` (`%LOOP_END`, and combinations with a predicate) | ctcond types 4–7, 14, 15 | transfer on the loop-end condition |
| `op ? %pcntN` | RLP/MRGC condition (gas accepts it as `? %pcntN`) | true while `pcnt ≤ N` |
| `pass %lcntex, @pN` | ELP special predicate 0 | true when `over` is set |
| `setbn rsz, rbs, rcur` | CS1 | define the rotating area of `%b[]` |
| `setbp psz` | CS1 | rotate `%pred0..psz` |

## Semantics [hw]

**Counting.** Each `alc` (when its condition holds), using the values
before it:

- `%LOOP_END` = `vlc && lcnt < 2 && ecnt == 0`;
- `over` := `%LOOP_END`;
- `lcnt` decreases while above 1, then drops to 0; `pcnt` decreases
  while above 0; `ecnt` decreases once `lcnt < 2`.

So a loop `ct %ctpr1 ? %NOT_LOOP_END` with `alc` in the same instruction
runs **`lcnt + ecnt` iterations** (one when `lcnt` is 0 or 1); `pcnt`
doesn't add any:

| `lcnt`, `ecnt`, `pcnt` | Iterations | `%lsr` after |
|---|---|---|
| 5, 0, 0 | 5 | `lcnt` 0, `over` 1, `vlc` 1 |
| 1, 0, 0 / 0, 0, 0 | 1 / 1 | the same |
| 5, 2, 0 | 7 | `ecnt` 0 |
| 5, 0, 3 / 5, 2, 3 | 5 / 7 | `pcnt` 0 |
| `vlc` = 0 | never ends | |

**Predicates.** With `lcnt` 5, `ecnt` 2, `pcnt` 3 (`pcnt` 3, 2, 1, 0,
0, 0, 0 over the 7 iterations), an operation under `? %pcnt0` ran in 4
iterations and under `? %pcnt1` in 5: `%pcntN` is true when `pcnt ≤ N`
(true from the first iteration whose `pcnt` reaches N). `%lcntex` was
false in every iteration, epilogue included, and true after the loop:
it reads `over`, which only the final `alc` sets, so it tells code after
the loop that the counter ended it.

**Stores** in an instruction with `loop_mode` (when `semc` = 0):

- suppressed while `pcnt > 0` (prologue iterations);
- in the last iteration (`%LOOP_END`), the instruction's stores
  numbered `strmd` and up are suppressed (the first store in channel
  order is 0): `strmd` 0 drops them all, 1 keeps the first;
- `semc` = 1, or an instruction without `loop_mode`, stores in every
  iteration.

| `lcnt`, `ecnt`, `pcnt`, `strmd` | Iterations that stored (of 7, or 5) |
|---|---|
| 5, 0, 0, 0 | 1–4 (not the last) |
| 5, 2, 3, 0 | 4–6 |
| 5, 2, 3, 1 | 4–7; with two stores: the first in 4–7, the second in 4–6 |
| 5, 2, 3, 2 (two stores) | both in 4–7 |
| 5, 2, 3, `semc` = 1 | 1–7 |

AAU stores (`staad … %aad0[ %aasti1 ]` with `incr`, as lcc pipelines
them) follow the same rules, and a suppressed one doesn't advance its
index either: with `pcnt` 3 the values of iterations 4, 5, 6 land in
elements 0, 1, 2 (and 7 in element 3 with `strmd` 1) [hw]. So a
pipelined loop's AAU stores need no address correction for the
prologue.

A **quad store counts as two stores** (v3 has only the AAU one in
64-bit mode, `staaq`; `stgdq` and `stapq` address through
protected-mode descriptors [source]): with `strmd` 0 the last iteration
drops it, with 2 it stores, and with 1, which would keep only its first
half, the `loop_mode` instruction raises SIGILL (`ILL_ILLOPC`) in that
iteration [hw]. A `strmd` count must therefore never split a quad
store. **On v5 a quad store is one store**: `stqp` (ALC2) and
`staaqp` (ALC5), one channel each, follow the rules with `strmd` 1
keeping the whole 16 bytes; with `stqp` in ALC2 and `std` in ALC5,
`strmd` 1 keeps the quad store and drops the doubleword (hw: Elbrus-8C2,
`v5qstores*`, `v5aaqstores`). Word stores (`staaw`) count
as one and advance by 4 bytes [hw].

**Loads are never suppressed**: an ordinary `ldd` in a `loop_mode`
instruction that reads past an array in epilogue iterations faults,
whatever `ldmc` (0, 1) and `ldovl` (0, 1, 2, 255) say. Loads that may
run past the data must be speculative (`ld,sm`, [speculation.md](speculation.md)),
as lcc's are.

**Array-prefetch reads** (`mova` in a `loop_mode` instruction) are
disabled in epilogue iterations unless `ldmc` = 1: with `lcnt` 5 and
`ecnt` 2, a `movad` of the stream 1, 2, 3, … returned 1–5 and then left
its destination unchanged (5, 5) with `ldmc` = 0, and continued (6, 7)
with `ldmc` = 1; `ldovl` 0, 1, 2 or 255 changed nothing [hw:
`tools/isa-probes/apb-loop.c`, `loopE`]. MCST's qemu has the same rule
(`mova` enabled when `!loop_mode || ldmc || !vlc || lcnt > 0`,
`translate-mova.c`) [source]. So epilogue iterations need no guard for
reads past the end of an array stream.

**Rotation.** `setbn rsz = R, rbs = B, rcur = C` makes `%b[]` a ring of
2(R + 1) 64-bit registers starting at window register 2B (`%b[n]` is
one 64-bit register, like `%dr`); `rcur` = C starts `%b[0]` C pairs up
the ring, at `%dr(2B + 2C)` (`rcur` 1, 2, 3 put `%b[0]` at `%dr18`,
`%dr20`, `%dr22` with B = 8). Each `abn` moves the base down one
register pair, so **the old `%b[0]` is the new `%b[2]`** (as
the guide's example says, 6.3.2): with `rsz` 3 (4 pairs from `%dr16`),
iterations writing `%b[0]` filled `%dr16`, `%dr22`, `%dr20`, `%dr18`,
`%dr16`, … `setbp psz = P` and `abp` do the same for `%pred0..P`: the
old `%pred0` is the new `%pred1`, the old `%predP` the new `%pred0`.

**Early exits and while loops.** `ct %ctpr1 ? ~%pred0 &&
%NOT_LOOP_END` leaves when `%pred0` becomes true or the count runs out:
with `lcnt` 10 and the predicate true in iteration 4 the loop ran 4
times, with it never true 10 times. With `vlc` = 0 `%NOT_LOOP_END` is
always true, so the same loop is a plain while loop that only the
predicate ends (7 iterations), still with `alc`, rotation and the store
rules' prologue part (the last-iteration part needs `%LOOP_END`, which
never comes).

**Calls.** A call doesn't touch `%lsr`: a loop calling a function that
leaves it alone counts right. A callee that runs its own loop leaves
`%lsr` finished (`lcnt` 0, `over` 1), and the caller's loop then ends
after the current iteration; saving `%lsr` with `rrd` before the call
and writing it back with `rwd` after (4 cycles before the next `alc`)
gives the right count. Restoring `%lsr` also resets `%ilcr`, which
matters only for array prefetch (apb.md).

**Interrupts.** 100,000,000 iterations of a loop whose rotating `%b[]`
chain counts them (each iteration writes `%b[2] + 1` to `%b[0]`) gave
the exact count and chain value with 10,965 `SIGALRM`s delivered during
the loop: the kernel saves and restores `%lsr`, `%ilcr` and the
rotation bases. A `loop_mode` store to a new page in each of 64
iterations page-faults every time and still stores every value, with
the right count.

**Timing.** A one-instruction `loop_mode` loop (`alc`, `ct ?
%NOT_LOOP_END`) runs 1,000 iterations in 1,001 cycles; with a second
instruction, 2,001: the transfer through a prepared `%ctpr1` is free
([control-transfer.md](control-transfer.md)).

## How lcc builds loops [lcc]

Counted loops (`for` with a known trip count):

lcc writes `%lsr` = `vlc` | `ldovl` 255 | `strmd` (1 if the loop
stores, else 0) | `lcnt` = n (`addd 0x20ff2000000000`, `insfd` of n),
at least 4 cycles before the loop, and never uses `pcnt` or `ecnt` in
the loops probed: it **peels the prologue** (the first stages run
before the loop, with `,sm` operations) and leaves the epilogue to the
last-iteration store rule and speculative loads. The kernel is one
instruction or a few, each with `loop_mode`, the last with `alc`, `abn`
(and `abp` when predicates rotate) and `ct %ctpr1 ? %NOT_LOOP_END`, the
CTPR prepared before the loop. Rotating `%b[]` carry values between
stages (`setbn rsz = 3..8`); stores often go through the array
prefetch unit (`staad … %aad0[ %aasti1 ]` with `incr`). Example,
`a[i] = b[i] * s` with `restrict`:

```
.L7: { loop_mode; alc alcf=1, alct=1; abn abnf=1, abnt=1
       ct %ctpr1 ? %NOT_LOOP_END
       fmuld,0,sm %b[7], %r2, %b[0]
       addd,1,sm 0x8, %b[11], %b[9]
       ldd,2,sm %r1, %b[11], %b[1]
       staad,5 %b[12], %aad0[ %aasti1 ]; incr,5 %aaincr0 }
```

Loops without a trip count (`while`, early exits): `%lsr` without `vlc`
(`0x20ff0000000000`: `ldovl` 255, `strmd` 1), the same `loop_mode`,
`alc`, `abn` and `abp`, and an exit through a rotated predicate
(`ct %ctpr1 ? %pred1`) or `ct %ctpr1 ? ~%pred0 && %NOT_LOOP_END`. In
these, lcc also conditions prologue work on `%pcntN`: in CoreMark's
`matrix_test` a DAM lock load runs under `? %pcnt14` and its check
under `? %pcnt0`. Over CoreMark and Linpack at `-O3`/`-O4` lcc uses
`%pcnt0` … `%pcnt14` and `rcur` up to 0x24, never `abg`, `%lcntex` or a
read of `%lsr`, and never a call inside a loop-mode loop.

## For a compiler

- A counted loop needs no compare: `rwd` the count into `%lsr` (with
  `vlc`) at least 4 cycles ahead, `disp %ctpr1, head` 5 cycles ahead,
  and end the body with `alc` and `ct %ctpr1 ? %NOT_LOOP_END` (GCC's
  `doloop_end`; port plan 7.7). An `ibranch` back edge would cost 6
  cycles per iteration.
- In a pipelined loop give every store `loop_mode` and either peel the
  prologue (lcc) or set `pcnt` to the number of prologue stages; set
  `strmd` to the number of stores of the final stage that must still
  write in the last iteration; make every load that can run ahead
  speculative.
- Values that live across stages go in `%b[]`; a value produced in
  stage s and used k iterations later is named `%b[n + 2k]` at the use.
- **Schedule with the crossing cost** (timing.md) on every dependence
  whose producer and consumer may land in different clusters, which is
  any dependence when gas picks the channels: a one-instruction kernel
  that carries an integer value to the next iteration at exactly its
  latency runs 1,000 iterations in 1,001 cycles with the consumer in the
  producer's cluster but 4,989 with it in the other one (a 4-cycle stall
  every iteration), and 1,001 again when the use waits one more
  iteration (`rot_*` cases, 4C and Elbrus-8C2 alike). Padding only adds
  stages; an operation's use of its own previous result stays in one
  channel and needs no padding. (Proof-of-concept back end: daxpy at
  II 1 ran at about 5 cycles per element with plain latencies, 0.75 ns
  with crossings added, lcc 0.70.)
- **No `loop_mode` is needed** if the kernel's stores all sit in its
  last stage and every other operation is speculative: with `lcnt` = n
  (and `vlc`, no `pcnt`, `ecnt` or `strmd`) the kernel runs n times;
  iteration k runs stage s of source iteration k + S − 1 − s, so the
  last S − 1 kernel iterations only run early stages of iterations past
  the end, whose loads are speculative and whose results nothing
  stores. The peeled prologue runs stages 0..S−2 of iterations 0..S−2
  under the names those values have after the skipped rotations.
  `abn abnf=1` also rotates on the iteration that leaves the loop, so
  afterwards the last iteration's value written as `%b[X]` is
  `%b[X + 2]` (`rot_exit`, 4C and 8C2), and one defined in stage D is
  `%b[X + 2 (S − D)]`. (Proof-of-concept back end, 4C and 8C2: sums,
  dot products, scaling, copies and daxpy for n = 1..1023, including
  n below the stage count and overlapping arrays.)
- **In a function that calls**, the ring must not stay above the
  outgoing pairs at a call: the callee would inherit the ring with them
  (`wsz − wbs` pairs, registers.md), and the PLT stub's `setwd wsz = 8`
  traps with SIGILL `ILL_ILLOPC` (proof-of-concept back end, 4C). lcc
  keeps the window at locals + 4 outgoing pairs (`setbn rsz = 3, rbs`
  at the outgoing pairs, calls with that `wbs`), and around the loop
  **grows the window** with a second `setwd` and a ring starting at the
  outgoing pairs (`setwd wsz = 0x1d; setbn rsz = 0xf, rbs = 0xd`), then
  shrinks it back after the loop (`setwd wsz = 0x11; setbn rsz = 0x3,
  rbs = 0xd, rcur = 0`) [lcc]. The proof-of-concept back end instead
  puts the ring between the locals and the outgoing pairs (calls with
  `wbs` above it, `setbn rsz = 3` at the outgoing pairs after the loop),
  which also works on the 4C and keeps the diagnostic values the last
  kernel iterations leave in the ring out of the argument registers.
- A loop with a call (lcc never pipelines one, guide 6.3.3) must save
  `%lsr` around it unless the callee is known not to run a loop:
  calls don't preserve it, they just don't change it.
- A loop without a known trip count can still use loop mode: `%lsr`
  without `vlc`, and an exit predicate in the back edge's condition.

## Global register rotation (`abg`, `%bgr`) [hw: Elbrus-8C2 and 4C, source]

Run on the Elbrus-8C2 (v5) and the 4C (v3) by `tools/isa-probes/abg.c`
(one case per process). Everything below holds on both.

`%bgr` (11 bits): `val` (bits 0–7) marks which of the eight physical
rotating registers are valid, `cur` (bits 8–10) is the rotation offset.
Processes start with `%bgr` = 0x0ff (`cur` 0, all valid), and user code
can read and write it with `rrs`/`rws`. `%g24`–`%g31` name physical
global `24 + ((cur + n) & 7)`; `%g0`–`%g23` don't rotate. Each 64-bit
half of a quad access (`movtq %qg24`, v5 `qpand %qpg24`) rotates on its
own, also with an odd `cur`.

It is an x87-style register stack (presumably for MCST's x86 binary
translator), `cur` being the top:

| Operation | Effect | Trap |
|---|---|---|
| `abg 1` (`abgd`, push) | `cur` −= 1 (mod 8), then set `val` bit `cur` | SIGFPE `FPE_FLTINV` if that bit was already set (overflow) |
| `abg 2` (`abgi`, pop) | clear `val` bit `cur`, then `cur` += 1 | never, even if the bit was clear |
| `abg 3` | as `abg 1` | as `abg 1` |
| read of `%g24`–`%g31` in ALC4/ALC5 | the value | SIGFPE `FPE_FLTINV` if the physical register's `val` bit is clear (`exc_fp_stack_u`) |
| the same read with `,sm`, or in ALC0–ALC3 | the value, not diagnostic | never |
| write of `%g24`–`%g31` | the value | never; `val` doesn't change |

The kernel's trap entry saves `%bgr` and sets it to 0x0ff before
touching the globals, restores it on return, and starts signal handlers
with 0x0ff (`trap_table.S.h`, `signal.c`); a trap taken with invalid
slots is harmless on both machines.

lcc never emits `abg` or touches `%bgr`, so a compiler can ignore them;
the ABI treats `%g24`–`%g31` as scratch (spec/abi/registers.md). v6
replaces `abg` with `abgc`/`rbgc` (bundle.md). Neither emulator runs
this: MCST's qemu stops at `rrs %bgr` ("exception handling is
unimplemented") and decodes `abg` without executing it; the community
qemu gives SIGILL.

## v6 [hw: Elbrus-2C3]

`loops.c` (with the v5 cases) gives the 8C2's results on the 2C3 except
the late `%lsr` write above: counts, `%pcnt`/`%lcntex`, store
suppression, rotation, `%lsr1`, quad stores and the behaviour across
signals and page faults are the same.

gas rejects `abg` for v6 ("not supported on elbrus-v6"), so `abg.c`
doesn't build there. v6 splits the x87-style stack into plain moves and
separate checks (`ctl6.c`, from user mode; `cur` is `%bgr` bits 8–10,
`val` bits 0–7, and a mask is rotated left by `cur`, so bit 0 means the
current top):

| Operation | Effect |
|---|---|
| `abgc N [? %predN]` (N 1–7, SS) | `cur` += N (mod 8); `val` unchanged, never traps (v5's `abgd`/`abgi` check `val` and trap) |
| `rbgc [? %predN]` | `cur` = 0; `val` unchanged |
| `modbgv a, dst` (ALC1/4) | `val` = (`val` & ~rot(a[7:0])) \| rot(a[15:8]): marks registers empty or full; writes 0 |
| `vfbgv a, b, dst` | SIGFPE `FPE_FLTINV` (an x87 stack fault) if a register in rot(b[7:0]) is full (overflow) or one in rot(b[15:8]) is empty (underflow); else writes 0 |
| `mkfsw a, b, dst` | the x87 status word with TOP = b mod 8 (semantics.md, "v6 operations") |

A C compiler still has no use for them.
