# Operation semantics

What the operations a C compiler emits actually compute: operand order,
inverted forms, extension, out-of-range shift counts, division corner
cases, compare predicates, NaN handling. [bundle.md](bundle.md) and
`binutils-ops.yaml` give encodings and channels; this page gives the
behaviour.

Status: **[hw]** observed on an Elbrus 4C (elbrus-v3) by
`tools/isa-probes/semantics.c` (wrappers generated by
`gen_semantics.py`); **[guide]** from the MCST programming guide, chapter
10, and for v5 operations on an Elbrus-8C2 by `sem5.c` (section "v5
operations"). MCST's qemu agrees with the hardware on every case it
can run except the quiet FP compares below (`semantics.c emu` skips the cases
that trap, at which it aborts: "exception handling is
unimplemented").
Latencies are in [timing.md](timing.md).

32-bit (`...s`) operations below were run under `setwd dbl = 0`: they
write the low half of the destination and keep the upper half
([registers.md](../abi/registers.md), `dbl`).

## Integer arithmetic and logic [hw]

| Operation | Result |
|---|---|
| `subd a, b, dst` | a − b. (`rsub` exists only as the second stage of combined operations.) |
| `andnd a, b, dst` | a & ~b (the **second** operand is inverted) |
| `ornd a, b, dst` | a \| ~b |
| `xornd a, b, dst` | a ^ ~b |
| `merged a, b, dst, pred` | **a when pred is false**, b when true: the reverse of `pred ? a : b`. `~%predN` is accepted. |
| `sxt n, src, dst` | n = 0, 1, 2: sign-extend 8, 16, 32 bits; n = 4, 5, 6: **zero**-extend 8, 16, 32 bits; 3 = 2, 7 = 6. The guide (10.3.8) has the sign bit the other way round; lcc emits `sxt 0x1` for `short`, `0x5` for `unsigned short` |
| `smulhd a, b`, `umulhd a, b` | high 64 bits of the signed / unsigned 128-bit product |
| `popcntd`, `popcnts` | number of set bits |
| `lzcntd`, `lzcnts` | leading zeros; 64 (32) for zero |
| `bitrevd`, `bitrevs` | bit reversal |

There are no 64-bit or 32-bit remainder operations: compute a % b as
a − (a / b) × b. (`smodx`/`umodx` give the remainder of a 64-bit by
32-bit division only, below.)

## Shifts and rotates [hw]

`shl`, `shr` (logical), `sar` (arithmetic), `scl`, `scr` (rotate left,
right), each in `s` (32-bit) and `d` (64-bit) forms. The count is taken
**modulo the operand width**: `shld` by 64 or 128 returns the operand
unchanged, by 65 shifts by 1; `shls` by 32 returns it unchanged. Only the
low bits of the count register matter: `shls` ignores the count's upper
32 bits (a count of `0xaaaaaaaa00000001` shifts by 1), `shld` by
`0xffffffffffffffff` shifts by 63. For GCC: `SHIFT_COUNT_TRUNCATED` holds.

## Division [hw]

| Case | Result |
|---|---|
| `sdivd MIN, -1`, `sdivs MIN, -1` | MIN, no trap |
| negative dividend | truncates toward zero (−7 / 2 = −3) |
| `sdivd`, `udivd`, `sdivs` by zero | **SIGFPE, `si_code` `FPE_INTDIV`** |

Division by zero traps, so a compiler must not move a division where it
might not have been executed, unless it uses the speculative form
(`,sm`), which defers the fault into the result tag.

## Integer compares [hw]

Compares write a predicate. All of them evaluate `a − b` and test it
like x86 flags; `cmp<c>db` compares 64 bits, `cmp<c>sb` 32 bits:

| `c` | True when |
|---|---|
| `o` | signed overflow of a − b |
| `b` | a < b unsigned |
| `e` | a = b |
| `be` | a ≤ b unsigned |
| `s` | a − b is negative (sign bit), not "signed less" |
| `p` | the low byte of a − b has even parity |
| `l` | a < b signed |
| `le` | a ≤ b signed |

There are no `ne`, `gt`, `ge`, `a`, `ae` forms: swap the operands or use
the negated predicate (`~%predN`) in the consumer.

`cmpand<c>db` / `cmpand<c>sb` test `a & b` instead of `a − b`, with `c`
in `e` (zero), `s` (bit 63, or 31, set), `p` (the low byte has an even
number of bits set, x86's PF) and `le` (≤ 0 signed). lcc tests the flag
bits of a register FP compare with them (`cmpandesb r, 0x40, %pred`).

## Floating-point compares [hw]

`fcmp<c>db` (double) and `fcmp<c>sb` (single) into a predicate, with `c`
in `eq`, `lt`, `le`, `uod` (unordered), `neq`, `nlt`, `nle`, `od`
(ordered). There is no `gt`/`ge`: swap the operands. With a NaN operand:

| Compares | Quiet NaN | Signalling NaN |
|---|---|---|
| `eq`, `neq`, `uod`, `od` | no exception | invalid |
| `lt`, `le`, `nlt`, `nle` | **invalid** | invalid |

So `lt`/`le` are the signalling compares IEEE 754 requires for C's `<`
and `<=`, and `eq`/`uod` are quiet. `neq`, `nlt`, `nle` are true for
unordered operands.

`fcmpud<d,s>f` and `fcmpod<d,s>f` compare into a register (32-bit
result; `d` double, `s` single operands) with x86's `ucomisd`/`comisd`
flag layout (ZF 0x40, PF 0x04, CF 0x01):

| a ? b | Result | Invalid flag, `ud` | Invalid flag, `od` |
|---|---|---|---|
| less | `0x01` | no | no |
| equal (also −0 = +0, inf = inf) | `0x40` | no | no |
| greater | `0x00` | no | no |
| unordered, quiet NaN | `0x45` | **no** | yes |
| unordered, signalling NaN | `0x45` | yes | yes |

`fcmp<c>d` and `fcmp<c>s` (same `c`) compare into a register: all ones
when true (64 bits, or the low 32 for `s`), else 0, with the exceptions
of the table above; they are x86 `cmpsd`/`cmpss` (`semx.c`, below).

`fcmpud*f` is the quiet compare that C's `isless` family needs; lcc
writes `isless (a, b)` as `fcmpuddf` then `r == 1`, `isgreaterequal`
as `r == 0 || r == 0x40` [lcc]. **MCST's qemu raises invalid for
`fcmpud*f` on a quiet NaN** (it treats it like `fcmpod*f`).

## FP min, max and combined operations [hw]

- `fmaxd a, b` / `fmind a, b` follow x86 `maxsd`/`minsd`, not C's
  `fmax`/`fmin`: if either operand is a NaN, or both are zeros, the result
  is **b**. (`fmaxd NaN, 1` = 1, `fmaxd 1, NaN` = NaN, `fmaxd 0, −0` =
  −0.) They implement `a > b ? a : b`, so a compiler may use them only
  where that is the source's semantics (or under `-ffinite-math-only`
  with no signed-zero concerns).
- **Combined operations** `X_Y a, b, c, dst` (gas operand order)
  compute **`Y(c, X(a, b))`**: the second stage takes `c` as its
  *first* operand. So `_sub` is **c − (a X b)** and `_rsub` is
  **(a X b) − c**, the reverse of what the names suggest:

  | Operation | Result |
  |---|---|
  | `fmul_addd` | (a × b) + c |
  | `fmul_subd` | c − (a × b) |
  | `fmul_rsubd` | (a × b) − c |
  | `fadd_subd`, `fsub_subd` | c − (a + b), c − (a − b) |

  The packed forms (`pf*_*`) apply the same rule lane by lane, with the
  packed stage operations `hadd(x, y)` = (x₀ + x₁, y₀ + y₁),
  `hsub(x, y)` = (x₀ − x₁, y₀ − y₁) and `addsub(x, y)` = (x₀ − y₀,
  x₁ + y₁) (low lane first): `pfmul_hadds a, b, c` = (c₀ + c₁,
  a₀b₀ + a₁b₁). All 63 combined FP operations of v3 (`f`/`pf` ×
  `add`/`sub`/`mul`/`hadd`/`hsub`/`addsub` × `add`/`sub`/`rsub`/
  `hadd`/`hsub`/`addsub`, `s`/`d`) follow it on the 4C and the
  Elbrus-8C2 (`tools/isa-probes/fcomb.c`, generated by
  `gen_fcomb.py`); the v5 `qpf*_*` family matches the community qemu
  (v5 operations, below), which builds every combined operation,
  integer ones included, as `op2(c, op1(a, b))`. The `f*_mul*` forms are
  v1 only.
- **Nothing special about them: a combined operation is two ordinary
  operations chained in one channel.** All 252 integer combined
  operations of v3 (`and`, `andn`, `or`, `orn`, `xor`, `xorn`, `add`,
  `sub`, `scl`, `scr`, `shl`, `shr`, `sar`, `getf` then `and` … `xorn`,
  `add`, `sub`, `rsub`, `s`/`d`; `merge_*`, which takes a predicate, not
  tried) give exactly what the two ordinary operations give run one
  after the other, `t = X a, b` then `Y c, t`, on the 4C and the
  Elbrus-8C2 over six input sets (`tools/isa-probes/icomb.c`, generated
  by `gen_icomb.py`). The encoding says the same [binutils, both qemus]:
  ALS opcode bits 0–4 hold **the first operation's own opcode** (`andd`
  0x01 makes `and_ord` 0x41, `getfd` 0x1f makes `getf_andd` 0x1f; for FP
  the opcode within the FP group, `faddd` 0x31 → 1, `fmuld` 0x39 → 9),
  and ALS bits 5–6 with the ALES group (`ICMB0`–`2`, `FCMB0`–`1`) hold
  **the second operation's opcode shifted right by one** (`and` 0, `or`
  2, `add` 8, `sub` 9; FP `add` 0, `sub` 1, `mul` 4). The second
  operation takes `c` as its first operand, so `sub` gives c − t, and
  the one slot that names no ordinary operation (6, `sxt`'s, for
  integers; 5 for FP) is `rsub`, t − c. The latency is the sum of the
  two (integer 1 + 1 = 2, FP 4 + 4 = 8, timing.md) and FP rounds after
  each stage (below); the integer forms run only in ALC1 and ALC4.
- `fmul_addd a, b, c, dst` = (a × b) + c with **two roundings** (not
  fused): `(1 + 2^-30)(1 − 2^-30) − 1` gives 0, not −2^-60. Combined FP
  operations may be used only under `-ffp-contract=fast`, never for
  `fma()`.

## Packed operations of v3 [hw]

`tools/isa-probes/semp.c` (generated by `gen_semp.py`) runs every v3
packed operation, 177 cases (the 64-bit packed integer and packed FP
operations, the immediate forms with six immediates each; not the
combined `pf*_*`, which `fcomb.c` covers, nor the tag operations) over
40 input sets on the 4C and the Elbrus-8C2, compared with both qemus
(as `sem5.c` does for v5). Everything matches the community qemu except
the points below, so its `target/e2k/helper_vec.c` describes the rest
(the proof-of-concept back end's finding I21, rechecked): lanes are
little-endian; compares give all-ones lanes; `pmerge a, b, m` takes b's
byte where m's byte is negative, else a's; `punpckl*` puts b's lanes at
even positions; `pack*` puts a's results in the high half; `pmaddh` is
x86 `pmaddwd` and `psadbw` its namesake; shifts take a count operand
(counts beyond the lane give 0, arithmetic shifts the sign). On v3 the
packed add, subtract, min, max, compare and average forms issue only in
ALC0/3, the multiplies, `pmaddh`, `psadbw`, `punpck*` and `pack*` only in
ALC1/4, shifts in either pair (binutils-ops.yaml), so 32-bit lanes rarely
beat six scalar channels. Where the hardware differs:

- **`pshufb` differs between v3 and v5.** Each byte of the third operand
  (the mask) picks a result byte: with bit 7 set, a constant (bits 5–6:
  0x00, 0x7f, 0x80, 0xff); otherwise bits 0–2 the byte and bit 3 the
  source (1: the first operand). On **v5** bits 4, 5, 6 then invert,
  bit-reverse and sign-replicate the picked byte (the community qemu's
  model; the 8C2 matches it in every byte); on **v3** they are ignored
  and the byte is copied as it is (the 4C, all 320 bytes). Both qemus
  apply the v5 rule to v3 too. A compiler targeting v3 must keep bits
  4–6 of plain selections clear (finding I21 took the v5 rule from
  qemu).
- **`psllql`, `psllqh`, `psrlql`, `psrlqh`** shift `src1:src2` (`src1`
  the high half) as one 128-bit value by **8 × imm** bits (bytes) and
  return its low (`l`) or high (`h`) half; the whole immediate counts,
  so 16 and more give 0 (both machines, every case). qemu shifts by
  `8 × imm` with a 64-bit TCG shift, which is undefined for counts of 64
  and more.
- **`pinsh src1, src2, imm`** inserts the low halfword of `src2` into
  halfword **imm & 3** of `src1` (gas warns about imm > 4; the hardware
  wraps, qemu leaves `src1` unchanged). **`pextrh src1, src2, imm`** gives
  halfword `imm` of `src1:src2` for imm ≤ 7; above 7 (gas: "undefined")
  the result differs between the 4C and the 8C2.
- **NaN choice** in `pfhadds`/`pfhsubs` when both lanes are NaN: the
  hardware returns the low lane's NaN, qemu the high one's.
- **Flags.** Packed FP operations set the denormal flag (as the scalar
  ones do; no emulator does). The packed compares `pfcmpeq`, `pfcmpneq`,
  `pfcmpod`, `pfcmpuod` are quiet: no invalid for a quiet NaN (both qemus
  raise it); `lt`/`le` signal, as the scalar ones. **The packed divides
  and square roots `pfdivs`, `pfdivd`, `pfsqrts`, `pfsqrttd` never set an
  exception flag** on either machine (no invalid, divide by zero,
  overflow, underflow or inexact; the values are the IEEE ones), where
  the scalar `fdivs`/`fdivd`/`fsqrts` do: code that needs `fenv` flags
  must not use them.
- `puttagd`/`puttags` raise SIGILL for some inputs (tag operations, not
  studied here); MCST's qemu aborts at them and also gets `pfdivs` and
  `pfsqrts` wrong in every case.

## Square root and reciprocals [hw]

All in ALC5 only (the divider, timing.md). `tools/isa-probes/sqrt.c`
(generated by `gen_sqrt.py`; `check_sqrt.py` compares with exactly
rounded results on the host) on the 4C and the Elbrus-8C2, which agree
bit for bit; four rounding modes, about 4,000 random inputs each plus
special values:

- **`fsqrts`, `fdivs`, `fdivd`** are correctly rounded in every mode.
- **Double square root is two operations**, `fsqrtid x, t` then
  `fsqrttd x, t, r` [guide 10.4.2], and the pair is correctly rounded in
  every mode (0 of 16,040 results differ), with IEEE flags (invalid for
  a negative or a signalling NaN, which becomes quiet).
- **`fsqrtid` is an intermediate in its own format**, not an
  approximation of √x: with x = m · 2^e (1 ≤ m < 2) it **keeps x's sign
  and exponent field** and replaces the significand by √(m · 2^(e mod
  2)) rounded to about 34 bits (low 18 significand bits zero; relative
  error ≤ 2^−34.6), so as a number it is √x · 2^⌈e/2⌉:
  `fsqrtid 2.0` = 2.828… (2√2), `fsqrtid 4.0` = 4.0. When the
  approximation rounds up to 2 the carry is dropped and the field reads
  1.0 (`fsqrtid 0x3fefffffffffffff` = `0x3fe0000000000000`). ±0, ±∞,
  NaNs and even negative numbers pass through unchanged (a signalling
  NaN is quieted); subnormal inputs get the smallest normal exponent;
  it raises **no flags**. `fsqrttd` halves the exponent, completes the
  significand and raises the flags.
- **`fsqrttd` needs exactly `fsqrtid`'s result**: it uses its second
  operand as the leading digits of the root, not as a seed it refines.
  Flipping one significand bit of it (bit 18, the lowest set one, or
  above) leaves the result wrong by about that bit's weight (at bit 18
  142 of 300 still right, above none), where one Newton step would
  correct a 2^−34 error. So a compiler must keep the pair together, and
  an emulator can compute `fsqrttd x, fsqrtid x` as the correctly
  rounded √x.
- **`frcps` and `frsqrts`** (single) are **12-bit approximations** of 1/x
  and 1/√x from a table: relative error ≤ 2^−11.6 in every mode, low 11
  significand bits zero (`frcps 1.0` = 0.99976, `frsqrts 2.0` = 0.70691);
  no flags ever; subnormal inputs give ±∞ (read as zero), ∞ gives 0,
  and `frsqrts` of a negative number gives a NaN without the invalid
  flag. They suit reciprocal and reciprocal-square-root estimates
  followed by Newton steps (`-ffast-math`); lcc never emits them, even
  with `-ffast` (`1.0f / sqrtf (x)` stays `fsqrts` + `fdivs`).
- **`pfsqrts` and `pfsqrttd` are not packed**: `pfsqrts` gives
  `fsqrts` of the low single and keeps the upper half (as every single
  operation does), and `pfsqrttd` gave `fsqrttd`'s results in every case
  tried.
- lcc emits `fsqrtid` + `fsqrttd` for `sqrt` and `fsqrts` for `sqrtf`,
  with a library call kept for `errno` unless `-ffast`.

## Other scalar operations [hw]

`tools/isa-probes/semx.c` (generated by `gen_semx.py`) runs the v3
scalar ALU operations no other probe runs, 166 cases (`merge_*` twice,
with its predicate false and true), and v4's `fscaled`/`fscales` on the
8C2, over 40 input sets (integers, doubles and floats: zero, normal,
infinite, quiet and signalling NaN, denormal; shift counts), recording
the destination and the `%pfpfr` flags. `check_semx.c` recomputes every
line on an x86 host: the FP operations with the SSE instruction named
below (taking its MXCSR flags, the same layout as `%pfpfr`), the integer
ones from the rules below. **All 6,640 lines of the 4C and 6,720 of the
Elbrus-8C2 match** (value, flags and signal); the two machines agree
except in the v4 operations the 4C lacks. So each rule below is exact on
those inputs:

| Operations | Result |
|---|---|
| `cmp<c>sb`, `cmpand<c>sb` | as the 64-bit forms (Integer compares) on the low 32 bits |
| `fcmp<c>sb` (predicate), `fcmp<c>s`, `fcmp<c>d` (register) | x86 `cmp<c>ss`/`cmp<c>sd`, `od` and `uod` being `cmpord`/`cmpunord`; exceptions as in "Floating-point compares" |
| `fsubs`, `fsubd` | a − b, as `subss`/`subsd` |
| `fmaxs`, `fmins` | `maxss`/`minss`: b if either is a NaN or both are zeros, as `fmaxd` |
| `fstoid` | single → 64-bit integer in the current rounding mode (`cvtss2si`) |
| `fstoidtr`, `fdtoidtr`, `fdtoistr` | truncating single → 64-bit, double → 64-bit, double → 32-bit (`cvttss2si`, `cvttsd2si`) |
| `idtofs`, `istofs`, `istofd` | 64-bit integer → single, 32-bit → single, 32-bit → double (`cvtsi2ss`, `cvtsi2sd`) |
| `fdtoifd a, b`, `fstoifs a, b` | **round b to an integral value**, a giving the mode as x86 `roundsd`/`roundss`' immediate: bits 0–1 the rounding mode, bit 2 "use `%pfpfr`'s", bit 3 suppresses inexact (also the `qp` forms of v5, below) |
| `fscaled a, b`, `fscales a, b` (v4+) | a × 2^b, b a signed 32-bit integer, rounded once, with IEEE flags (C's `ldexp`/`scalbn` in one operation) |
| `smulx a, b`, `umulx a, b` | the 64-bit product of two 32-bit operands, signed or unsigned |
| `sdivx a, b`, `udivx a, b` | 64-bit a ÷ 32-bit b, truncated, into 32 bits; **SIGFPE** when b = 0 or the quotient doesn't fit 32 bits (signed or unsigned) |
| `smodx a, b`, `umodx a, b` | the remainder of the same division (sign of a); SIGFPE when b = 0 or when a × 2^z, z the number of leading zeros of \|b\| as a 32-bit value, is 2^64 or more (unsigned) or outside [−2^64, 2^64) (signed) |
| `insfs a, b, c`, `insfd a, b, c` | rotate a right by b's bits 0–4 (`d`: 0–5), then replace its low *n* bits by c's, *n* = b's bits 6–10 (`d`: 6–11); higher bits of b are ignored (in `insfd` bits 13 and 15 choose tags [source: community qemu]) |
| `mpsadbh a, b` | four 16-bit sums: lane *i* = Σ\_j \|a.byte[i + j] − b.byte[j]\|, j = 0..3 (x86 `mpsadbw` on 64 bits) |
| `merge_<y> a, b, c, dst, pred` | y(c, merge(a, b, pred)): **a when the predicate is false**, b when true (as `merged`), then the combined operation's second stage, `rsub` included |

A conversion out of range or of a NaN gives x86's integer indefinite
(0x8000000000000000, 0x80000000) and invalid. FP flags include the
denormal flag for a denormal operand (as for every FP operation,
below). The modulo operations are the odd ones: they trap
where their quotient wouldn't fit only through that leading-zero shift,
so `umodx 0xffffffffffffffff, 0x80000000` gives 0x7fffffff (a 33-bit
quotient) while `umodx 0xfedcba9876543210, 0x7fc00000` traps
(`tools/isa-probes/divx.c`: 894 dividend and divisor pairs around the
limit, the 4C and the 8C2 alike, all following the rule). A compiler
can use `udivx`/`sdivx` for a 64 ÷ 32 division whose quotient is known
to fit (x86's `div`), and a remainder only when it knows the dividend is
below 2^32 × b.

What lcc uses of these (its C library, libm and libstdc++ for v3, and
small tests at `-O3`): **`insfs`/`insfd` for bit-field stores**
(`p->y = v` for a 7-bit field at bit 5 is `insfs word, 0x1c5, v` then
`scls 5` to rotate the word back), about 2,800 times in those three
libraries; **`smulx`/`umulx` for `(long) a * b`** of two 32-bit values;
`fscales` for `scalbnf` under `-ffast` on v4+ (`ldexp` stays a call).
It computes `int % int` as `sdivs`, `muls`, `subs`, and `smodx` appears
once in its C library, on a sign-extended 32-bit dividend (where the
limit can't be reached); it never uses `sdivx`/`udivx`, `mpsadbh` or the
flag operations below.

### x86 flag operations

A family meant for x86 binary translation computes an operation and
returns **the x86 EFLAGS it would set** instead of its value, in the
EFLAGS layout (CF 0x01, PF 0x04, AF 0x10, ZF 0x40, SF 0x80, OF 0x800)
as a 32-bit result; the suffix gives the x86 operand width (`_fb` 8,
`_fh` 16, `_fw` 32, `_fd` 64 bits; `s` operations have the first three,
`d` operations `_fd`):

| Operations | Flags |
|---|---|
| `adds_f*`, `subs_f*`, `addd_fd`, `subd_fd` | x86 `add`/`sub` of a and b: all six |
| `ands_f*`, `andns_f*`, `ors_f*`, `orns_f*`, `xors_f*`, `xorns_f*` and the `d` forms | ZF, SF, PF of the result; CF, OF, AF 0 (the `n` forms invert b first) |
| `incs_f* a, b, c`, `decs_f* a, b, c` and `_fd` | **a + b / a − b** (b is the step), with CF taken from c's bit 0 (the old flags, as x86 `inc`/`dec` keep CF) |
| `shls_f*`, `shrs_f*`, `sars_f*` `a, b, c` and `_fd` | count b modulo 32 (`s`) or 64 (`d`), as x86 masks it; count 0: c's flags unchanged. ZF, SF, PF from the low bits of the whole register shifted (so higher bits of a shift into an 8-bit result); CF the last bit shifted out of the operand of that width (zero- or sign-extended, so 0 or its sign once the count passes the width); OF as x86 for a count of 1, else 0; AF 0 |
| `scls_f*`, `scrs_f*` `a, b, c` and `_fd` | x86 `rol`/`ror` within the width: CF and OF (count 1 only, else 0) set, the other flags c's |
| `umulx_f*`, `smulx_f*` | CF = OF = 1 when bits *w* to 2*w* − 1 of the product of the 32-bit operands are not the zero (sign) extension of bits 0 to *w* − 1, as x86 `mul`/`imul` for *w*-bit operands; the rest 0 |
| `cctop<c> f` | predicate: x86 condition `c` evaluated on f as EFLAGS: `o` OF, `b` CF, `e` ZF, `be` CF\|ZF, `s` SF, `p` PF, `l` SF ≠ OF, `le` ZF \| (SF ≠ OF) |

Neither qemu implements the flag forms (both stop at them), and the
community qemu evaluates `cctopl` as true when SF and OF are both set.
lcc doesn't emit any of them for C: its `__builtin_add_overflow` on
`int` is ten operations of compares and selects, where `adds_fw` then
`cctopo` give the overflow predicate (and `cmposb a, b` alone gives
subtraction's; their latencies are not measured).

Apart from the flag forms, MCST's qemu differs from the hardware in this
sweep only in FP flags:
no denormal flag, invalid for a quiet NaN in the quiet compares (`eq`,
`neq`, `od`, `uod`), and inexact despite bit 3 in `fdtoifd`/`fstoifs`.

## 80-bit operations [hw]

`tools/isa-probes/semfx.c` (generated by `gen_semfx.py`) runs every
80-bit operation of v3 and the conversions and moves around it (87
operations: `fx<op><b><r>` for `add`, `sub`, `rsub`, `mul`, `div` with a
second operand `b` and a result `r` single, double or 80-bit;
`fxcmp<c><b>b`/`f`; conversions; the square root steps), and lcc's
square root sequence `fxsqrti` → `fxsqrtu` → `fxsqrtt`, over 94 operand
sets (special values, random ones, and four that tell one rounding from
two) in six `%fpcr` settings (the four rounding modes at extended
precision, and double and single precision control). `check_semfx.c`
redoes each line with the host's x87. The 4C and the Elbrus-8C2 give
the same 50,760 lines, and **every line with an x87 counterpart matches
x87 code in value and flags** (43,428 lines):

- **Rounding as x87 code does**: the result is rounded to the precision
  control's precision, then to its own format. So `fxadddd` (80-bit +
  double → double) under extended precision gives what `fadd` then
  `fstp` to a double give, **rounding twice**: (1 + 2^−53) + 2^−80 gives
  1.0 where one rounding would give 1 + 2^−52 (538 lines tell the two
  apart, all the x87 way); under single precision control it rounds to
  single. lcc folds `(double) (x + d)` (x `long double`) into one
  `fxadddd` at `-O3`, also without `-ffast`, and that gives exactly its
  `-O0` sequence's result (`fdtofx`, `fxaddxx`, `fxtofd`), also checked
  on the 8C2 with the tie above.
- Operands of type `s` and `d` are converted exactly; an 80-bit result
  keeps 64 significand bits; the `s`/`d` results are IEEE values.
- **Compares**: `fxcmp<c><b>b` into a predicate follows the scalar
  rules (quiet `eq`, `neq`, `uod`, `od`; signalling `lt`, `le`, `nlt`,
  `nle`); `fxcmpud<b>f` / `fxcmpod<b>f` give the x86 flag layout of
  `fcmpud*f`, the `ud` form quiet and the `od` form signalling on a quiet
  NaN (`fucomi`/`fcomi`).
- **Conversions**: `fxtoid`, `fxtois` round in the current mode
  (`fistp`), `fxtoidtr`, `fxtoistr` truncate (`fisttp`), out of range
  gives the integer indefinite and invalid; `fxtofd`, `fxtofs`, `idtofx`,
  `istofx`, `fstofx` as x87 loads and stores. `movx` copies, `movxa`
  clears the sign (`fabs`), `movxc` flips it (`fchs`), NaNs included,
  without flags.
- **Square root**: lcc computes `sqrtl` (under `-ffast`; otherwise a
  call) as `fxsqrtixx a, t; fxsqrtuxx a, t, t; fxsqrttxx a, t, r`, and
  that chain equals x87 `fsqrt` in every line and mode (the `s` and `d`
  operand forms too). The steps alone have no x87 counterpart and are
  not decoded (as for `fsqrtid`, the intermediate is in its own format).
- **`fxdivt*`** (`fxdivtss`, `fxdivtsx`, `fxdivtdd`, `fxdivtdx`) give
  invalid and a NaN for most ordinary operands: a division step that
  needs a prepared operand, not decoded. lcc divides with `fxdivxx`,
  `fxdivdd` and the other plain forms.

So the 80-bit operations implement x87 arithmetic exactly, and a
compiler can map `long double` operations one to one, including an
operation whose result is converted straight to `double` or `float`.
(MCST's qemu uses `%pfpfr` instead of `%fpcr`/`%fpsr` for them:
AGENTS.md, gotchas.)

## Predicate logic [hw, source]

A CLP (bundle.md, "PLS") combines two primary predicates `@pK`, each
optionally negated: `andp` and `landp` both give `c0 && c1`, `movep`
copies [source: MCST qemu `translate-pls.c`]. They differ in diagnostic
(tagged) predicates, which a speculative compare of a diagnostic value
yields (speculation.md) (`tools/isa-probes/preds.c`, `lp_*`; 4C and
Elbrus-8C2 alike; a `ct` on the result traps with SIGILL `ILL_ILLOPN` if
it is diagnostic):

| Operation | first operand | second operand | Result |
|---|---|---|---|
| `landp` | false | diagnostic | **false, clean** |
| `landp` | true | diagnostic | diagnostic |
| `landp` | diagnostic | false or true | diagnostic |
| `andp` | false or true | diagnostic | diagnostic |

So only `landp`'s second operand is lazy, as C's `&&` is: a chain
`landp (landp (c1, c2), c3)` evaluates `c1 && c2 && c3` with each
condition computed speculatively under the ones before it, which is
how lcc merges a chain of branches into one (zlib's `longest_match`)
and how a loop combines an exit test with a second, speculative one.
Chains are limited to two levels in one instruction (bundle.md).

## Byte-swapped memory accesses (MAS bit 3) [hw]

The MAS byte of a load or store (`mas=N` in gas) is, for ordinary
accesses [source: kernel `asm/mas.h`, MCST qemu `mas-format.h`]: bits
0–2 `mod` (the access kind: speculation.md, atomics.md), **bit 3 `be`**,
bit 4 `m1`, bits 5–6 the cache hints (timing.md, "Memory"). `be` = 1
makes the access big-endian: the loaded bytes are reversed, then
zero-extended; a store writes its low bytes most significant first
(`tools/isa-probes/mas_be.c`, 4C and Elbrus-8C2 alike; memory holding
`01 02 … 10`):

| Access with `mas=0x8` | Result |
|---|---|
| `ldb` | 0x01 (one byte: nothing to swap) |
| `ldh`, `ldw`, `ldd` | 0x0102, 0x01020304, 0x0102030405060708 |
| `ldd,sm …, mas=0xb` (fully speculative, mod 3, + `be`) | 0x0102030405060708 |
| `sth`, `stw`, `std`, `stb` of 0x0102030405060708 | `07 08`, `05 06 07 08`, `01 02 … 08`, `08` |
| `ldqp`, `stqp` (v5) | all 16 bytes reversed |
| any of them at an address not aligned to its size (`ldh` +1, `ldw` +1/+2, `ldd` +3/+4, `sth` +1, `stw` +2, `std` +4) | **SIGBUS**, where the same access without `be` works |

A swapped load costs nothing extra: 64 dependent `ldd` take 309 cycles
with and without `be`, on both machines. Both qemus agree on the data
(`mas_be.c` at `-O3`, 4C and Elbrus-8C2 alike).

lcc folds a byte swap into the access only under **`-ffast`** (from
`-O2`; none of its component options alone does it), its set of
"potentially dangerous optimisations": the misaligned case above. At
`-O3` and `-O4`, `__builtin_bswap64 (*p)` is a plain `ldd` plus `pshufb`
with the mask 0x0001020304050607, `sa->sin_port = htons (port)` a 64-bit
mask literal (0x8080808080800001; 0x8080808000010203 for `htonl`),
`sxt`, `pshufb` and `sth`, and `ntohs`/`ntohl` loads add `sxt`,
`pshufb`, `sxt`; with `-ffast` each is one `ldh`/`ldw`/`ldd`/`sth`/`stw`
with `mas=0x8`. Its `__builtin_e2k_ld_*_be` / `st_*_be` builtins
(`e2kintrin.h`, 32, 64 and 128 bits) always use the bit. What the fold
buys (`mas_be.c` with `mas_be_loops.c`, both at `-O3`; same on the 4C
and the 8C2):

- **latency on a dependent load path**: 64 dependent `ldd` + `pshufb`
  (the swapped value used as the next address) take 629 cycles against
  309 with `mas=0x8`, 5 cycles a step (the shuffle plus the packed →
  integer crossing, timing.md). Scalar code that parses big-endian data
  sits on this path;
- **on the store side, instructions and a little latency**: 32 steps of
  swap, store and reload with `ldw mas=0x8` take 437 cycles through
  lcc's sequence and 421 with `stw mas=0x8` on the 4C, 501 and 425 on
  the 8C2 (the store-to-load round trip hides most of the swap); filling
  a `sockaddr_in` with a run-time port and address spends two of the
  four literal slots and four ALU operations on the swaps;
- **nothing in a pipelined loop**: lcc's sum and copy loops over 2,048
  elements in L1 run at the same speed either way (4C 1.49 ns, 8C2 0.78
  ns per element), the `pshufb` taking a free ALU slot and its latency
  only a stage; the MAS form is a few instructions shorter.

So a compiler should fold a byte swap into an adjacent load or store of
16 to 64 bits **when the access is known to be aligned to its size**
(GCC: `MEM_ALIGN` at least the mode's size; members of packed structures
and accesses through byte pointers don't qualify): never worse, 5 cycles
better on dependent load paths, two to four operations and a literal
fewer each time. (The array prefetch unit has its own `be` bit in
`mova`, apb.md.)

## The denormal flag [hw]

FP operations set `%pfpfr` bit 1 (`de`, denormal; no `FE_` name in
glibc) when an operand is denormal, as x86 does: `1 + 4.9e-324`
(`faddd`) gives flags 0x22 (denormal and inexact), `fmuld` and the
compare `fcmpltd` with a denormal operand 0x02, and `fadds` the same, on
the 4C and the Elbrus-8C2 alike; so do the v5 packed operations (below).
Neither qemu ever sets it.

## v5 operations [hw: Elbrus-8C2]

`tools/isa-probes/sem5.c` (generated by `gen_sem5.py`) runs every ALU
operation whose first ISA version is 5 (703 after leaving out loads,
stores and protected-mode operations: the 128-bit packed `qp*` family,
`plog`/`qplog` with all 256 tables, `addcd`/`subcd` with carry,
`getfz*`, `psrc*`, `pmullw` and others) over 40 sets of three 128-bit
inputs (integers, doubles and floats: zero, normal, infinite, quiet and
signalling NaN, denormal; shift counts), recording all 128 bits of the
result and the exception flags. On the 8C2 and under both emulators
(`-cpu elbrus-v5`):

- **Results**: all 703 operations give the same 128 bits on hardware
  and under the community qemu, so its implementations
  (`target/e2k/helper_*.c`, `fp_helper.c`) describe what they compute.
  MCST's qemu agrees except for `qpslld` and `qpsrld`: on hardware a
  count of 64 or more gives 0 (as x86 `psllq`/`psrlq`), MCST's qemu takes
  the count modulo 64.
- **Packed compares are quiet where the scalar ones are**: `qpfcmpeq*`,
  `qpfcmpneq*`, `qpfcmpod*` and `qpfcmpuod*` (both widths) raise no
  invalid on a quiet NaN; both emulators raise it (the same emulator
  error as for `fcmpud*f`, above). The `lt`/`le` forms signal, as the
  scalar ones do.
- **Round to integral** (`qpfdtoifd`, `qpfstoifs`; the first operand is
  the mode): bits 0–1 the rounding mode, bit 2 "use `%pfpfr`'s", and
  **bit 3 suppresses the inexact flag**, as in x86 `roundpd`'s immediate
  (every case with bit 3 set raised no inexact, every case without it
  did). MCST's qemu leaves bit 3 unimplemented ("TODO") and raises it.
- The denormal flag, above; otherwise the flags agree.
- No operation trapped (no SIGILL or SIGFPE with flags masked as the
  kernel leaves them).

So for v5 operations a compiler may take the community qemu's helpers
as the reference, minding the three points above.

## Other facts [guide]

- `%idr` (read with `rrd`, also in user mode): CPU model in bits 0–7,
  revision 8–11, L2 write-back length 12–14, core 15–19, node 20–23,
  hardware virtualisation 24–28 (kernel `e2k_idr_t`). Models (kernel
  `bootinfo.h`): E2S (4C) 3, E8C 7, E1C+ 8, E8C2 9, E12C 0xa, E16C 0xb,
  E2C3 0xc, E8V7 0xe; 0 under virtualisation. The 4C reads `0x312203`
  on core 2 of node 3 [hw]; MCST's qemu `0x2203` (`-cpu elbrus-v3`) and
  `0x2309` (`elbrus-v5`). lcc's `__builtin_cpu_is` uses its own model
  numbers ([source-compat.md](../abi/source-compat.md)).
- `getsp src2, dst`: src2 is a 32-bit signed operand; a negative value
  allocates that many bytes on the user stack, and dst receives the new
  stack pointer (guide 10.7.1; `getsp 0, dst` reads it).
- 80-bit operations (`fx*`): "80-bit operations" above; their registers
  and FP state: [registers.md](../abi/registers.md), "Extended parts and
  `long double`".
